# Хакатон «Tender Hack — Санкт-Петербург»

[cite_start]**Основная задача:** Разработка интеллектуального сервиса поиска цен в открытых источниках[cite: 1, 3, 4, 5].

## 🎯 Ключевой функционал сервиса
* [cite_start]**Обязательные источники:** Автоматический сбор данных с трех маркетплейсов (Яндекс Маркет, Ozon, Wildberries)[cite: 16].
* **Неформализованные источники:** Поиск цен на неформализованных ресурсах Рунета с использованием бесплатных инструментов. [cite_start]Четвертым источником не может быть фиксированный сайт или еще один маркетплейс[cite: 21, 93].
* [cite_start]**Необходимые данные:** По каждой позиции пользователю должны быть доступны: изображение, наименование, характеристики, цена и ссылка на источник[cite: 17, 49].
* [cite_start]**Группировка:** Результаты должны быть сгруппированы по источникам с указанием количества предложений и цен (например, «на Ozon найдено X предложений за Y руб.»)[cite: 18, 48].
* [cite_start]**Обработка запроса:** Система должна учитывать регион, исправлять опечатки и применять синонимы для повышения релевантности[cite: 20, 46, 47].
* [cite_start]**Интерфейс:** Необходимо обеспечить интуитивно понятный веб-интерфейс[cite: 27].
* [cite_start]**Исключения:** Делать авторизацию и сохранение результатов **не требуется**[cite: 35].

## ⚠️ Строгие ограничения и технические требования
* [cite_start]**ОС:** Решение должно работать на операционной системе семейства Linux[cite: 56].
* [cite_start]**Автономность:** Сервис должен функционировать ИСКЛЮЧИТЕЛЬНО на серверах команды, без привлечения сторонних ресурсов[cite: 57].
* [cite_start]**Полный запрет внешних API:** Запрещено использовать API сторонних поисковых систем (Яндекс.Поиск, Google Search, Bing) и внешние API больших языковых моделей (OpenAI GPT, Google Gemini, Anthropic Claude и др.)[cite: 58, 59, 60].
* [cite_start]**Запрет Low-code/No-code:** Использование таких платформ запрещено[cite: 67].
* **ML-модели:** Разрешены любые открытые нейросети. Однако предпочтение отдается легковесным решениям с высокой скоростью инференса. [cite_start]Необоснованное применение «тяжелых» моделей снизит оценку[cite: 68, 69, 70].
* [cite_start]**Антифрод и парсинг:** Необходимо разработать и обосновать способ обхода ограничений на частоту запросов (блокировок) внешних сервисов[cite: 22, 23].

## 🏆 Критерии оценки
* [cite_start]**40 баллов:** Наличие работоспособного прототипа[cite: 86].
* [cite_start]**25 баллов:** Корректность сбора данных (картинка, название, характеристики, цена, ссылка) с трех обязательных маркетплейсов (Яндекс Маркет, Ozon, Wildberries)[cite: 92].
* [cite_start]**25 баллов:** Извлечение данных из неформализованных ресурсов Рунета с помощью бесплатных поисковых движков[cite: 93].
* [cite_start]**10 баллов:** Качество поиска (синонимы, опечатки, регион), удобство интерфейса и обоснованность обхода блокировок[cite: 94].

## 📊 Формат защиты
* [cite_start]**Схема:** Обязательна схема реализации в нотации BPMN с указанием примененного ПО[cite: 34].
* **Этап 1:** Презентация до 5 минут со схемой BPMN. Параллельно второй участник демонстрирует реальные кейсы. [cite_start]Максимум 100 баллов[cite: 74, 75, 77].
* **Этап 2 (Топ-5 команд):** Отправка исходного кода (репозиторий или архив). Презентация до 10 минут + 10 минут на вопросы жюри. [cite_start]Баллы суммируются с первым этапом[cite: 78, 79, 80].
