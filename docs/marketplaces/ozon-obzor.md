# Ozon: обзор для нового человека в проекте

Этот текст объясняет, **как у нас устроен поиск товаров на Ozon**: какие файлы за что отвечают, в каком порядке всё вызывается и зачем нужны браузер, ML и парсинг HTML.

**Техническая шпаргалка:** [ozon.md](ozon.md)

---

## Зачем вообще столько файлов

Ozon — самый сложный источник в проекте. Wildberries отдаёт JSON одним запросом, Яндекс Маркет — HTML страницу. **Ozon активно блокирует «роботов»** (защита WAF/antibot). Обычный HTTP-запрос (как через curl) почти всегда получает капчу или «Доступ ограничен».

Поэтому для Ozon мы:

1. Открываем **настоящий Chrome** через библиотеку **nodriver** (как будто зашёл человек).
2. Сначала собираем **много** товаров с страницы поиска.
3. **Отбираем** самые подходящие запросу (нейросеть).
4. Заходим на **карточки** выбранных товаров и вытаскиваем описание и характеристики.

Каждый шаг вынесен в отдельный файл — так проще читать код и тестировать по частям.

---

## Карта файлов (кто за что)

Представь цепочку: **оркестратор** → **ozon.py** → остальные модули.

```
Пользователь ввёл «iphone 15»
         │
         ▼
  orchestrator/search.py     ← общий поиск по всем маркетплейсам
         │
         ▼
  scrapers/ozon.py           ← «входная дверь» Ozon: выбор режима, формат ответа
         │
         ├── ozon_browser.py      ← браузер Chrome
         │        └── two_stage_ozon.py   ← сценарий: поиск → ML → карточки
         │                 ├── ozon_seo_common.py  ← вытащить данные из HTML
         │                 └── ozon_ml_filter.py   ← отбор top-5 по смыслу
         │
         └── ozon_public_scraper/  ← запасной путь без браузера (редко на демо)
```

| Файл | Простыми словами |
|------|------------------|
| **`ozon.py`** | Главный класс `OzonScraper`. Получает запрос от API, решает **как** искать (браузер или public), переводит сырые данные в модель `Product` для фронта. |
| **`ozon_browser.py`** | Запускает Chrome, открывает страницы, ждёт загрузки, ловит блокировки WAF. Одна «сессия браузера» на весь поиск. |
| **`two_stage_ozon.py`** | Сценарий из трёх шагов: широкий поиск → ML-фильтр → обход карточек. Всё в **одном** открытом браузере. |
| **`ozon_seo_common.py`** | Читает HTML/JSON со страницы и достаёт название, цену, ссылку, описание, характеристики. Не ходит в сеть — только разбор текста страницы. |
| **`ozon_ml_filter.py`** | Небольшая нейросеть (rubert-tiny2): сравнивает запрос пользователя с названиями товаров и оставляет **5 самых похожих**. |
| **`cache_manager.py`** | Опционально сохраняет готовый результат на диск, чтобы при повторном запросе не открывать браузер снова. |
| **`ozon_public_scraper/`** | Альтернатива: ищет ссылки через MeiliSearch + SearXNG и качает страницы по HTTP. На Ozon часто блокируется — для демо не основной путь. |
| **`browser_semaphore.py`** | «Очередь»: одновременно может работать **только один** Chrome для Ozon (иначе капча и зависшие процессы). |

## `ozon.py` — входная точка

Это тонкий слой между общим API и «тяжёлой» логикой.

```python
async def search(self, request):
    if settings.ozon_use_browser:
        return await self._search_browser(request)   # обычно так
    return await self._search_public(request)        # запасной вариант
```

### Режим браузера (`_search_browser`)

1. Вызывает `ozon_browser.search_products(запрос)`.
2. Получает список словарей `{title, price, url, image, description, ...}`.
3. Если Ozon заблокировал — ставит статус `blocked_by_waf` и пустой список (на фронте показывается предупреждение).
4. Иначе превращает каждый словарь в **`Product`** — единый формат для всего приложения (цена в **копейках**, как у WB и YM).

### Режим public (`_search_public`)

Используется, если в `.env` выключен браузер: `OZON_USE_BROWSER=false`. Ищет через поисковые индексы и Open Graph-теги на странице. Проще, но на живом Ozon часто 403.

## Основной пайплайн (two-stage + браузер)

Это то, что включается по умолчанию: `OZON_USE_BROWSER=true` и `OZON_TWO_STAGE_ENABLED=true`.

### Шаг 0. Очередь и один браузер

Перед стартом код ждёт **семафор** (`browser_semaphore.py`): если другой пользователь уже гоняет Ozon, новый запрос встаёт в очередь.

Затем `run_browser_pipeline()` в `ozon_browser.py`:

- открывает Chrome (nodriver);
- **заходит на главную ozon.ru** (warmup) — без этого часто сразу капча;
- выполняет сценарий из `two_stage_ozon.py`;
- закрывает браузер.

**Почему один браузер на всё:** если для поиска и для каждой карточки открывать Chrome заново, Ozon быстрее распознаёт бота и показывает captcha.

### Шаг 1. Широкий поиск (broad search)

- Открывается URL вида `https://www.ozon.ru/search/?text=ваш+запрос`.
- Код ждёт, пока на странице появятся товары (есть ссылки `/product/` и символ ₽).
- **`ozon_seo_common.extract_broad_search_products`** вытаскивает до **36** preview-товаров: название, цена, ссылка, картинка.
- Берутся только товары из **основной сетки**, без блоков «реклама» и «рекомендации».

На этом шаге **ещё нет** полного описания — только то, что видно в выдаче.

### Шаг 2. ML-фильтр (top-5)

36 товаров — много; заходить на каждую карточку долго (минуты). **`ozon_ml_filter.py`**:

- загружает модель `cointegrated/rubert-tiny2` (русский sentence-transformers);
- сравнивает ваш запрос с **названием** каждого товара;
- оставляет **5 самых похожих** по смыслу.

Пример: запрос «айфон 15» — отсечёт чехлы и стёкла, если они попали в выдачу.

### Шаг 3. Enrich — заход на карточки

Для каждого из 5 товаров **в том же браузере**:

1. Пауза ~5 секунд (чтобы не спамить Ozon).
2. Открывается страница товара.
3. Ждём, пока подгрузится SPA (описание в `og:description` или много виджетов на странице).
4. **`extract_product_enrichment`** достаёт описание и характеристики.
5. В поле `description` склеивается текст + блок «Характеристики: • …».

Если одна карточка не загрузилась — **остальные всё равно возвращаются** (с данными из preview).

### Шаг 4. Обратно в `ozon.py`

Список словарей → объекты `Product` → оркестратор → API → React UI.

## `ozon_browser.py` — что делает браузер

| Термин | Что это |
|--------|---------|
| **nodriver** | Python-библиотека: управляет Chrome без «robot»-флага webdriver. |
| **WAF / antibot** | Защита Ozon: captcha, страница «Доступ ограничен». |
| **warmup** | Сначала заход на главную — «прогрев» cookies. |
| **polling** | Каждые 2 секунды проверяем HTML: страница уже готова или ещё капча? |

При блокировке возвращается статус **`blocked_by_waf`** — не «ошибка сервера», а «Ozon нас не пустил».

**Docker vs хост:** в Docker с виртуальным экраном (Xvfb) Ozon часто блокирует. На демо используют **`./start_demo.sh`** — API на хосте с нормальным `DISPLAY`. См. [run.md](../run.md).

## `ozon_seo_common.py` — парсинг без магии

Ozon — SPA: в первом HTML мало данных, часть лежит в JSON внутри страницы (`__NEXT_DATA__`, `widgetStates`).

Парсер пробует по порядку:

1. JSON из скриптов на странице (надёжнее).
2. Если не вышло — разбор HTML-карточек (`div.tile-root` и т.п.).

Две главные функции:

- **`extract_broad_search_products`** — товары со **страницы поиска**.
- **`extract_product_enrichment`** — описание и характеристики со **страницы товара**.

Цены переводятся в **копейки** (целое число), как в остальном API.

---

## `ozon_ml_filter.py` — зачем нейросеть

Это **не** генерация текста и **не** ChatGPT. Модель только считает «насколько название товара похоже на запрос» (cosine similarity эмбеддингов).

Если модель не загрузилась — fallback: просто первые 5 товаров из broad search.

---

## Кэш (`cache_manager.py`)

По умолчанию **выключен** (`OZON_BROWSER_CACHE_ENABLED=false`).

Если включить — результат поиска по запросу пишется на диск (библиотека **diskcache**). Повторный такой же запрос не открывает Chrome.

Это **отдельный** кэш от Redis (Redis у нас для Wildberries и Яндекс Маркета).

---

## Запасной путь: `ozon_public_scraper/`

Кратко:

1. Параллельно: поиск URL в **MeiliSearch** и через **SearXNG** (`site:ozon.ru запрос`).
2. Объединение ссылок, без дубликатов.
3. HTTP-загрузка страниц, разбор Open Graph (`og:title`, `og:price`, …).

Без Chrome, быстрее, но на боевом Ozon часто **403**. Включение: `OZON_USE_BROWSER=false`.

---

## Как Ozon вписан в общий поиск

В `orchestrator/search.py`:

1. **Параллельно** идут Wildberries, Яндекс Маркет, «другие источники».
2. **После них** — Ozon (он медленный, 35–180 секунд, держит единственный Chrome).

Пользователь на фронте видит результаты WB/YM раньше, Ozon догружается последним (polling каждые 3 секунды).

## Настройки (.env) — самое нужное

```env
OZON_USE_BROWSER=true              # браузер (да) или public (нет)
OZON_TWO_STAGE_ENABLED=true        # broad → ML → enrich
OZON_BROAD_SEARCH_MAX=36           # сколько товаров с выдачи
OZON_ML_TOP_K=5                    # сколько оставить после ML
OZON_ENRICH_ENABLED=true           # заходить на карточки
OZON_ENRICH_DELAY_SECONDS=5        # пауза между карточками
OZON_PIPELINE_TIMEOUT_SECONDS=180  # макс. время всего пайплайна
OZON_BROWSER_WARMUP_HOME=true      # заход на главную перед поиском
OZON_BROWSER_CACHE_ENABLED=false   # дисковый кэш
```

## Типичные проблемы (для отладки)

| Что видишь | Вероятная причина |
|------------|-------------------|
| «Доступ ограничен» / пустой Ozon | WAF, нет warmup, Docker вместо хоста |
| Только название и цена, нет описания | enrich не успел / WAF на карточке / мало `OZON_ENRICH_WAIT_SECONDS` |
| Очень долго | норма для 5 карточек; cold start ML-модели |
| Зависший Chrome | `./kill_zombies.sh` |
